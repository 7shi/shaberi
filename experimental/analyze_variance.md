# analyze_variance.py - 評価者間分散分析ツール

## 概要

`analyze_variance.py`は、Shaberi評価フレームワークにおける構造化出力の効果を定量的に分析するツールです。従来形式（自由形式テキスト出力）と新形式（構造化JSON出力）の評価者間分散を比較し、構造化出力による評価品質向上効果を数値で実証します。

## 背景

### 評価者間分散の問題

LLM-as-a-Judge手法における重要な課題の一つは、**評価者間の一貫性**です。同じ回答を異なる評価者（LLMモデル）が評価した際に、スコアにばらつきが生じることがあります。この分散が大きいほど：

- 評価結果の信頼性が低下
- モデル比較の正確性が損なわれる
- 研究の再現性が困難になる

### 構造化出力による改善仮説

Shaberiプロジェクトでは、従来の自由形式評価から構造化JSON出力への移行により、以下の改善効果を仮説として立てました：

1. **項目別評価の強制**: 各評価基準を個別に検証することで一貫性向上
2. **理由付けの義務化**: 曖昧な採点を排除し客観的根拠を要求
3. **計算ミスの防止**: 手動計算から自動集計への移行

この仮説を検証するため、実際のスコアデータから評価者間分散を計算し、構造化出力の効果を定量的に分析するツールが必要となりました。

## ツールの設計思想

### 1. 評価対象モデル別分析

従来のベンチマーク全体での分散分析ではなく、**評価対象モデル別**に分散を計算することで：

- モデル性能の違いによる影響を排除
- 純粋な評価者間の一貫性を測定
- より精密な改善効果の検証が可能

### 2. 形式自動判別

スコアデータから評価形式を自動判別：

```python
def parse_evaluator_model(evaluator_model_path):
    if evaluator_model_path.endswith('.json'):
        # 従来形式: judge_xxx/model.json
        return evaluator, model, "legacy"
    else:
        # 新形式: evaluator/model
        return evaluator, model, "structured"
```

### 3. 統計的指標の包括計算

各評価形式について以下を計算：
- **平均スコア**: 評価者間の平均値
- **標準偏差**: 分散の平方根
- **分散**: 評価者間のばらつきの指標
- **範囲**: 最高点と最低点の差
- **分散減少率**: 構造化出力による改善度

## 技術的特徴

### 1. 堅牢なエラーハンドリング

```python
# 最小評価者数のチェック
if len(legacy_scores) < min_evaluators and len(structured_scores) < min_evaluators:
    continue

# ゼロ除算の防止
if legacy_var > 0 and structured_var is not None:
    variance_reduction = (legacy_var - structured_var) / legacy_var * 100
```

### 2. 柔軟な設定オプション

- `--min-evaluators`: 分析に必要な最小評価者数（デフォルト: 3）
- `--benchmark`: 特定ベンチマークの分析
- `--all-benchmarks`: 全ベンチマークの一括分析
- `--output`: 結果のファイル保存

### 3. 統計的妥当性の確保

- **母分散の使用**: `statistics.variance()`でn-1ではなくnで除算
- **効果量の計算**: パーセンテージでの改善率表示
- **異常値の識別**: 分散増加ケースの自動検出

## 使用方法

### 基本的な実行

```bash
# Tengu Benchmarkの分析
uv run analyze_variance.py -b lightblue/tengu_bench

# 全ベンチマークの分析
uv run analyze_variance.py --all-benchmarks

# 結果をファイルに保存
uv run analyze_variance.py -b lightblue/tengu_bench --output variance_analysis.txt
```

### 高度な設定

```bash
# 最小評価者数を2に変更（より多くのモデルを分析）
uv run analyze_variance.py -b lightblue/tengu_bench --min-evaluators 2

# カスタムスコアファイルの使用
uv run analyze_variance.py -b lightblue/tengu_bench --input custom_scores.yaml
```

## 出力の解釈

### 1. 分散減少率の意味

- **+87.5%**: 構造化出力により分散が87.5%減少（大幅改善）
- **+27.6%**: 構造化出力により分散が27.6%減少（改善）
- **-139.7%**: 構造化出力で分散が増加（要調査、通常は元々低分散の場合）

### 2. 統計的信頼性

- **最小評価者数**: デフォルト3人以上で統計的妥当性を確保
- **両形式比較**: 同一評価対象モデルでの比較により公正性担保
- **効果サイズ**: 50%を超える改善は実用的に意義が大きい

### 3. 実用的な判断基準

**改善効果の評価**:
- **80%以上**: 非常に大きな改善効果
- **50-80%**: 大きな改善効果
- **20-50%**: 中程度の改善効果
- **0-20%**: 小さな改善効果
- **負の値**: 分散増加（原因分析が必要）

## 技術的限界と注意点

### 1. 統計的前提

- **正規分布の仮定**: 分散計算は正規分布を前提
- **独立性の仮定**: 各評価者の判定が独立であることを前提
- **同質性の仮定**: 評価対象モデルの性能が同等レベルであることを前提

### 2. データ品質への依存

- **欠損データ**: 評価者数が少ない場合は分析対象外
- **異常値**: 極端なスコアが分散に大きく影響
- **バイアス**: 評価者モデルの性能差が結果に影響する可能性

### 3. 解釈の注意点

- **因果関係**: 分散減少が構造化出力のみに起因するとは限らない
- **一般化**: 特定ベンチマークでの結果が他に適用できるとは限らない
- **時間的変化**: 評価者モデルのアップデートにより結果が変動する可能性
