# check_criteria.py

## なぜこの実装が存在するか

### 形式統一の自動化
**Problem**: Shaberi評価フレームワークでFew-shot形式から構造化出力（JSONスキーマ）への移行時、120件のTengu Benchmarkタスクの評価項目形式を手動確認するのは非効率的でエラーが発生しやすい。

**Solution**: 評価項目の形式適合性を自動検証するチェッカーを実装し、人的ミスを排除しつつ効率的な品質管理を実現。

## 調査結果

Tengu Benchmark（data/）120件の調査結果：

### 2つの形式パターン

**形式1: 単層構造（97件）**
```markdown
[評価項目]
- 答えが867万円である:3点
- 自然な日本語である:1点
[評価するモデルの回答]
```

**形式2: 階層構造（23件）**
```markdown
[評価項目]
- 文章中の以下の情報を含んでいる
  - 取引デジタルフォームの定義:2点
- 自然な日本語である:1点
[評価するモデルの回答]
```

### 形式仕様
- **配点**: 全て10点満点、「X点」形式
- **階層**: 2スペースインデント、親項目は点数なし
- **構成**: `[評価項目]` → リスト → 空行 → `[評価するモデルの回答]`

### 例外ケース（修正済み）

- **スペース不足**: ハイフン直後のスペース漏れ（1件）
- **複数空行**: セクション間の連続空行（2件）

### 仕様策定への影響

この調査結果に基づき、JSONスキーマ生成時には以下を考慮する必要があります：

1. **階層構造の統合**: 階層項目は「親項目：子項目」形式でスキーマに含める
   - 例: `"文章中の以下の情報を含んでいる：取引デジタルフォームの定義"`
2. **配点の自動抽出**: 正規表現`r':(\d+)点$'`で確実に抽出可能
3. **項目名の正規化**: 長い説明文をJSONキーとして使用する際の文字制限対応

## 検証ロジック

### 状態遷移モデル

スクリプトは4つの状態を持つ状態機械として動作します：

1. **search**: `[評価項目]`セクションを探索
2. **reading_criteria**: 通常の評価項目を読み取り
3. **checking_indent**: インデント階層の子項目を読み取り
4. **waiting_for_next**: 空行後の`[評価するモデルの回答]`を待機

### 形式パターン

#### 通常の評価項目
- **パターン**: `r'-.+:\d+点$'`
- **例**: `- 自然な日本語である:1点`

#### 階層の親項目
- **パターン**: `r'-.+$'`（末尾に点数なし）
- **例**: `- 文章中の以下の情報を含んでいる`

#### インデントされた子項目
- **パターン**: `r'  -.+:\d+点$'`（2スペースのインデント）
- **例**: `  - 取引デジタルフォームの定義:2点`

### アルゴリズムの特徴

#### 同一行再処理
状態変更時に`continue`を使用することで、同じ行を新しい状態で再評価します：

```python
elif re.match(r'-.+$', line):
    # 階層の親項目、インデント調査モードに移行
    state = 'checking_indent'
```

これにより、階層構造の親項目を適切に処理できます。

#### 柔軟な空行処理
複数の連続する空行にも対応し、最初の非空行が`[評価するモデルの回答]`であれば正常とみなします。

#### エラー早期検出
期待しない形式が見つかった時点で即座に`False`を返し、効率的な検証を実現します。

## 使用方法

### 実行コマンド
```bash
cd experimental
uv run check_criteria.py
```

### 前提条件
- `data/`ディレクトリが存在すること
- ディレクトリ内に`.md`ファイルが存在すること
- Python 3.6以上

### 出力例

**すべて正常な場合：**
```
結果: 120/120 件が正常
```

**エラーがある場合：**
```
✗ 021.md
✗ 081.md
✗ 096.md

結果: 117/120 件が正常
```

## 技術仕様

- **依存**: 標準ライブラリのみ（`re`, `pathlib`）
- **パフォーマンス**: エラー早期検出、ファイル単位処理
- **エラーハンドリング**: 個別捕捉、処理継続

## 検出される問題例

1. **不正な階層構造**: インデントが2スペース以外
2. **不正な終了**: `[評価するモデルの回答]`以外のセクション
