# tengu.py - Tengu Benchmark構造化出力評価システム

## 概要

`tengu.py`は、Tengu Benchmark評価タスクにおいて、構造化出力（JSONスキーマ）形式による評価を実行するメインスクリプトです。統合LLMレイヤー（`llm.py`）を通じてOpenAI APIとGemini APIの両方に対応し、指定されたタスク番号とモデル回答ファイルを使用して自動評価を行い、構造化された評価結果を出力します。

## 背景

**Problem**: 従来のFew-shot形式では、LLMの計算ミス、出力形式不安定、パース処理複雑、トークン浪費などの問題が発生。

**Solution**: JSONスキーマを活用した構造化出力により、計算の確実性、形式保証、処理効率化、コスト最適化を実現。

## アーキテクチャ

**データフロー**: モデル回答JSON → タスクファイル読み込み(MD+Schema) → LLM評価 → 構造化結果出力

**ファイル構成**:
- **入力**: `data/xxx.md`(プロンプト), `data/xxx.json`(スキーマ), モデル回答ファイル
- **出力**: 構造化評価結果JSON, 自動計算合計点数

## 主要機能

1. **回答データ一括読み込み**: JSONL形式から全タスクを事前ロード、動的タスク数対応
2. **load_task_files()**: タスク別評価プロンプトとJSONスキーマの読み込み
3. **スキーマ検証統合**: LLM生成JSONのリアルタイム適合性チェック
4. **evaluate_task()**: 構造化出力による評価実行、OpenAI/Gemini自動判別
5. **calculate_score()**: 構造化結果からの確実な合計点数計算

## 使用方法

### コマンドライン実行

```bash
# 基本的な使用方法
uv run tengu.py <model_file> -n <task_number> [-m <model>]
uv run tengu.py <model_file> --all [-m <model>]

# オプション
--force          # 既存ファイル上書き
-st -1           # 温度リトライ無効(o4-mini用)
--max-length N   # 最大トークン数指定
```

### argparseによる引数処理

**引数仕様：**
- `json_file`: モデル回答ファイルのパス（位置引数）
- `-n/--task-number`: 評価するタスク番号（単一タスク評価時必須）
- `--all`: 全タスクを評価（-nと相互排他）
- `-m/--model`: 評価モデル名（デフォルト: gemini-2.5-flash）
- `--force`: 既存評価結果の上書き
- `-st/--start-temperature`: 開始温度を指定（0-100）。負値の場合は温度調整リトライを無効化（o4-miniモデルでは-1推奨）
- `--max-length`: 最大トークン数（デフォルト: 8192）

**引数検証：**
- `--all`なし & `-n`なし → エラー（どちらか必須）
- `--all`あり & `-n`あり → エラー（同時指定不可）
- `-n`指定時の範囲チェック（1 ≤ n ≤ タスク数）

**ヘルプ表示：**
```bash
uv run tengu.py -h
```

### 実行結果例

- **単一タスク**: スキーマ検証、点数計算、JSON保存
- **エラー時**: スキーマ違反の詳細表示
- **全タスク**: 進捗バー、既存ファイルスキップ機能
- **出力**: `answer`, `evaluation`, `summary`, `score`を含むJSON

## 技術仕様

### 依存関係

**内部モジュール：**
- `llm7shi.compat`: LLM API統合レイヤー
  - `generate_with_schema()`: 統一インターフェース（OpenAI/Gemini自動判別）
- `llm7shi`: デフォルト設定
  - `DEFAULT_MODEL`: デフォルトモデル名（gemini-2.5-flash）
- `tengu.py`: 評価システム（このファイル内）
  - `generate_with_temperature_retry()`: 温度調整リトライ機能
- `validate_schema.py`: スキーマ検証機能
  - `validate_json_with_schema()`: JSONデータ即座検証

### API仕様

**使用モデル**: 
- デフォルト: `gemini-2.5-flash`
- `-m`オプションで指定可能
- モデル名プレフィックスで自動判別:
  - `gemini-*`: Gemini API使用
  - その他: OpenAI API使用

**設定パラメータ：**
- `temperature=0`: 決定論的出力（初期値）
- 温度リトライ: JSONパースエラー時に0.0→1.0まで0.05刻みで自動調整
- JSONスキーマによる構造化出力制御
- **生成長制限**: `MAX_LENGTH = 8192`による出力文字数制限

### ファイル形式

**ファイル形式**:
- **入力**: JSONL形式のモデル回答、Markdownプロンプト、JSONスキーマ
- **出力**: `judge/{評価者}/{回答者}/{xxx}.json`に構造化結果保存
- **構造**: `answer`, `evaluation`, `summary`, `score`を含むJSON

## エラーハンドリング

### 例外の種類

**ファイル関連：**
- `FileNotFoundError`: 必要ファイルの不存在
- `ValueError`: プロンプト形式エラー
- `json.JSONDecodeError`: JSON解析エラー

**API関連：**
- API呼び出しエラー
- レスポンス形式エラー
- スキーマ違反エラー

### 対処方針

1. **差分的エラー処理**: 
   - **単一タスク評価**: エラー時に例外を再発生（`raise`）
   - **全タスク評価**: エラーメッセージ表示して継続
2. **重複実行防止**: 既存ファイルの自動スキップ（`--force`で上書き可能）
3. **事前検証**: `check_criteria.py`による形式確認
4. **デバッグ支援**: プロンプト内容の出力表示（コメントアウト可能）

## generate_with_temperature_retry機能

**概要**: JSONパースエラー時に温度を段階的に上げて自動リトライ、構造化出力の成功率を向上。

**主要機能**:
- **温度リトライ**: 0.0から1.0まで0.05刻みで段階的試行
- **o4-mini対応**: `-st -1`で温度パラメータ無効化（必須）
- **Ctrl+C対応**: 中断時に続行確認（y/N）
- **デバッグ支援**: 各エラーの詳細表示

**実用効果**: 高い成功率、自動回復、決定論的優先、通常1-3回で成功
